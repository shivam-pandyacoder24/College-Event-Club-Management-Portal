    Data structures

    Ten topics, each doing a real job on this site. Every structure is written by hand, and the panels show what each one holds right now.

    Array

    Holds the event information

    Every event is one element of a single array. The hash table and the search tree do not store events of their own. They store positions in this array, and the array holds the details.

    Read by position: O(1) js/app/portal.js

    Searching

    Runs the search box and the date filter

    The search box uses linear search, because a word can match an event’s name, club, venue or tags, and those are in no order. The date filter uses binary search on the events sorted by date: one search finds where the range starts, another finds where it ends.

    Linear: O(n). Binary: O(log n) js/dsa/search.js

    Sorting

    Orders the events

    Merge sort handles date, popularity and category. It is stable, so events that tie stay in date order. Quick sort handles names, which never tie.

    Both: O(n log n) on average js/dsa/sort.js

    Linked list

    Keeps each club’s members

    A club’s members are a singly linked list, in the order they joined. Joining links a new node after the tail. Leaving unlinks one node by pointing the node before it at the node after it.

    Add at tail: O(1). Remove: O(n) js/dsa/linked-list.js

    Stack

    Powers Undo and Recently viewed

    Whatever happened last is on top. Undo pops the top action and reverses it, so actions are undone in the reverse of the order they happened. Opening an event pushes it onto the recently viewed stack.

    Push and pop: O(1) js/dsa/stack.js

    Queue

    Runs each waiting list

    When an event is full, a student who registers joins the rear of its queue. When someone cancels, the student at the front is dequeued and gets the seat. Nobody can be skipped.

    Enqueue and dequeue: O(1) js/dsa/queue.js

    Tree

    Organises the event categories

    Categories form a general tree, where a node can have any number of children. Choosing a category shows every event in its subtree, and the breadcrumb is the path from the root.

    Find a category: O(n) js/dsa/category-tree.js

    Binary search tree

    Finds events by number

    Event numbers sit in a binary search tree: smaller to the left, larger to the right. A lookup follows one branch down. Because the tree keeps the numbers in order, it can also name the closest numbers when the one you typed does not exist.

    Lookup: O(log n) js/dsa/bst.js

    Graph

    Connects clubs, events and students

    Each club, event and student is a node, and each relationship is a labelled edge. Depth-first search follows a club’s events to build its trail. Breadth-first search finds the shortest chain between any two nodes. Suggestions come from walking a few edges out from you.

    Both searches: O(nodes + edges) js/dsa/graph.js

    Hashing

    Looks up students and events by ID

    A hash function turns a student ID into a bucket number, so signing in checks one short chain instead of every student. Keys that land in the same bucket are chained together, and the table doubles its buckets when it gets crowded.

    Lookup: O(1) on average js/dsa/hash-table.js
